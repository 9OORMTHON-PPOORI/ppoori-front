## 🕹 실행 방법

```bash
# 1. 환경변수 파일 생성
cp .env.example .env

# 2. 의존성 설치 및 실행
yarn
yarn dev
```

`.env`의 값을 비워 두어도 빌드와 실행은 정상 동작합니다. API 프록시만 비활성화되고,
어떤 경로가 꺼졌는지 빌드 로그에 경고로 남습니다.

| 환경변수                     | 설명                                                                    |
| ---------------------------- | ----------------------------------------------------------------------- |
| `POLICY_API_ORIGIN`          | 정책 조회 API 오리진. `/api/policy/*` 요청이 이 주소로 프록시됩니다     |
| `RECOMMEND_API_ORIGIN`       | 추천 API 오리진. `/api/recommend/*` 요청이 이 주소로 프록시됩니다       |
| `NEXT_PUBLIC_SERVICE_CLOSED` | 종료 안내 노출 여부. 미지정 시 종료로 동작하며 `false`면 추천 화면 노출 |

앞의 두 값은 서버에서 실행되는 `rewrites`에서만 쓰이므로 `NEXT_PUBLIC_` 접두사를
붙이지 않습니다. 접두사를 붙이면 백엔드 주소가 클라이언트 번들에 그대로 포함되어
프록시를 경유하는 의미가 사라집니다.

### 검증

```bash
yarn typecheck     # tsc --noEmit
yarn lint:strict   # 경고 0건 기준
yarn format:check  # Prettier
yarn test          # Vitest
yarn build         # 프로덕션 빌드
```

동일한 5단계가 `main`·`develop` 대상 push와 PR에서 CI로 실행됩니다.

```
src/
├── app/                     # App Router 라우트

│   └── common/
```

## 🧭 기술적 선택

### API 프록시로 Mixed Content 회피

백엔드가 HTTP로 서빙되어 HTTPS 페이지에서 직접 호출하면 브라우저가 요청을 차단합니다.
브라우저는 같은 출처의 `/api/*`로만 요청하고 Next.js `rewrites`가 실제 백엔드로
전달합니다. axios `baseURL`을 `"/api"` 상대 경로로 고정해, 환경변수 설정 여부와
무관하게 항상 프록시를 경유하도록 코드로 강제했습니다.

### 응답 표기와 도메인 타입 분리

백엔드는 `like_count`, `curr_idx` 같은 snake_case로 응답합니다. 이 표기를 컴포넌트까지
흘리면 API 스키마 변경이 UI 수정으로 직결됩니다. 응답 타입과 매퍼는 `lib/api` 안에만
두고, 화면은 `likeCount`, `currentIndex`만 압니다. 배열 필드가 `null`로 오는 경우도
매퍼에서 빈 배열로 정규화해 화면마다 방어 코드를 두지 않습니다.

### 실패의 정규화

axios 인터셉터에서 `AxiosError`를 `ApiError`로 변환합니다. 상태 코드별 메시지,
타임아웃, 네트워크 단절을 구분하므로 화면은 `error.message`만 표시하면 되고
axios 구현에 결합되지 않습니다.

### 쿼리 키 팩토리와 캐시 무효화

키 문자열이 훅마다 흩어져 있으면 무효화 대상을 안전하게 지정할 수 없습니다.
`policyKeys` 팩토리로 키 생성을 모으고, 반응·댓글 뮤테이션이 성공하면 훅이 상세와
목록을 함께 무효화합니다. 화면은 `refetch`를 알 필요가 없습니다.

### persist 스토어의 하이드레이션

Zustand `persist`는 기본적으로 모듈 평가 시점에 localStorage를 복원합니다. 그러면
서버가 그린 HTML(기본값)과 첫 클라이언트 렌더(복원값)가 어긋나 하이드레이션 불일치가
발생합니다. `skipHydration`으로 자동 복원을 끄고, 하이드레이션 이후 명시적으로 복원한
뒤에만 저장값에 의존하는 화면을 그립니다.

### 종료 처리를 플래그로

기능을 주석 처리해 끄면 죽은 코드가 남고 어느 쪽이 살아 있는지 파일만 봐서는 알 수
없습니다. `IS_SERVICE_CLOSED`로 분기해 종료 안내와 추천 화면을 모두 살아 있는 코드로
유지했습니다. 빌드 타임 상수라 사용하지 않는 쪽은 번들에서 제거됩니다.

### 접근성

조작 가능한 요소는 모두 `button`·`a`로 구현해 키보드로 접근할 수 있게 하고, 선택 상태는
`aria-pressed`로 노출합니다. `eslint-plugin-jsx-a11y`를 CI에 포함해 회귀를 막습니다.
